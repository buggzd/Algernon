# Repository Guidelines

## Project Structure & Module Organization
This is a Vite + Tauri desktop app for brain-training exercises.
- `index.html`, `app.js`, and `styles.css` contain the web UI, app logic, and styling.
- `brain-training-camp.html` is a standalone HTML variant; keep shared behavior aligned with `app.js` when changing exercises.
- `src-tauri/` contains the Rust/Tauri shell: `src-tauri/src/` for Rust entry points, `tauri.conf.json` for app configuration, `capabilities/` for permissions, and `icons/` for bundle assets.
- `dist/` is generated by Vite; do not edit it directly.
- There is currently no dedicated `tests/` directory.

## Build, Test, and Development Commands
- `npm install` installs JavaScript and Tauri CLI dependencies from `package-lock.json`.
- `npm run dev` starts the Vite dev server on `http://localhost:1420` using the strict port configured in `vite.config.ts`.
- `npm run build` builds the frontend into `dist/` with esbuild minification unless `TAURI_DEBUG` is set.
- `npm run tauri dev` runs the full desktop app in development mode.
- `npm run tauri build` creates production Tauri bundles.
- `cd src-tauri && cargo check` validates Rust code quickly without building installers.

## Coding Style & Naming Conventions
Use ES modules and modern JavaScript. Follow the existing style in `app.js`: two-space indentation inside blocks, semicolons, camelCase for variables/functions, and UPPER_SNAKE_CASE for constants such as `STORAGE_KEY`. Keep DOM ids/classes descriptive and kebab-case in HTML/CSS. Rust code should follow `rustfmt` defaults; run `cd src-tauri && cargo fmt` before submitting Rust changes.

## Testing Guidelines
No automated test suite is configured yet. For frontend changes, manually run `npm run dev` and verify affected exercises in the browser. For desktop persistence, permissions, or dialogs, run `npm run tauri dev` and confirm records/preferences are saved correctly. For Rust/Tauri changes, run `cargo check` from `src-tauri/`. If adding tests, prefer colocated unit tests or a new `tests/` directory with clear `*.test.*` naming.

## Commit & Pull Request Guidelines
Git history currently uses short initial commits (`init`, `Initial commit`). Continue with concise, imperative commit messages, e.g. `Add focus-mode preference saving`. Pull requests should include a summary, manual test steps, linked issues when applicable, and screenshots or screen recordings for UI changes. Note any changes to Tauri permissions, file storage, or bundle configuration.

## Security & Configuration Tips
Do not commit local records, generated bundles, or machine-specific config. Keep Tauri capabilities minimal when adding filesystem or dialog access, and document why new permissions are required.
