# Repository Guidelines

## Project Structure & Module Organization
This is a Vite + Tauri desktop app for brain-training exercises.
- `index.html`, `app.js`, and `styles.css` contain the web UI, app logic, and styling.
- `brain-training-camp.html` is a standalone HTML variant; keep shared behavior aligned with `app.js` when changing exercises.
- `src-tauri/` contains the Rust/Tauri shell, including `src/`, `tauri.conf.json`, `capabilities/`, and `icons/`.
- `.github/workflows/release.yml` builds release bundles from version tags.
- `dist/` is generated by Vite; do not edit it directly.

## Build, Test, and Development Commands
- `npm install` installs dependencies from `package-lock.json`.
- `npm run dev` starts the Vite dev server on `http://localhost:1420` using the strict port configured in `vite.config.ts`.
- `npm run build` builds the frontend into `dist/` with esbuild minification unless `TAURI_DEBUG` is set.
- `npm run tauri dev` runs the full desktop app in development mode.
- `npm run tauri build` creates production Tauri bundles.
- `cd src-tauri && cargo check` validates Rust code quickly without building installers.

## Release Automation
Pushing a `v*` Git tag starts the `Release` workflow. It builds Linux, Windows, macOS Apple Silicon, and macOS Intel Tauri bundles, then uploads them to a draft GitHub Release. To ship a commit, run `git tag v1.0.0 <commit-sha>` and `git push origin v1.0.0`. Use manual dispatch to rebuild an existing tag. Keep tags aligned with `package.json` and `src-tauri/tauri.conf.json`.

## Coding Style & Naming Conventions
Use ES modules and modern JavaScript. Follow `app.js`: two-space indentation, semicolons, camelCase for variables/functions, and UPPER_SNAKE_CASE for constants such as `STORAGE_KEY`. Keep DOM ids/classes kebab-case. Rust should follow `rustfmt`; run `cd src-tauri && cargo fmt` before submitting Rust changes.

## Testing Guidelines
No automated test suite is configured yet. For frontend changes, run `npm run dev` and verify affected exercises. For persistence, permissions, or dialogs, run `npm run tauri dev`. For Rust/Tauri changes, run `cargo check` from `src-tauri/`. If adding tests, prefer colocated unit tests or `tests/*.test.*`.

## Commit & Pull Request Guidelines
Git history currently uses short initial commits (`init`, `Initial commit`). Continue with concise, imperative commit messages, e.g. `Add focus-mode preference saving`. Pull requests should include a summary, manual test steps, linked issues when applicable, and screenshots for UI changes. Note changes to Tauri permissions, storage, bundle config, or release workflow behavior.

## Security & Configuration Tips
Do not commit local records, generated bundles, or machine-specific config. Keep Tauri capabilities minimal, and document new filesystem or dialog permissions.
